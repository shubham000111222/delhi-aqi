# Decisions and open questions

## Decisions taken while building this

| # | Decision | Reason | Consequence |
| --- | --- | --- | --- |
| 1 | **Synthetic feed is the default** | the build environment has no exchange connectivity; a deterministic seeded market makes every test and demo reproducible | `--feed ccxt` is implemented but unproven; swap it after one testnet run |
| 2 | **Single sequential event loop, no worker pool** | determinism and replayability beat throughput at this scale (5 symbols, 2 signal timeframes) | 15-minute strategy bars, 1-minute data; do not expect HFT |
| 3 | **Decimal everywhere for money, float only for indicator math** | float money bugs are unrecoverable; float indicators are fine | candle → float conversion at the strategy boundary |
| 4 | **SQLite for state, with `:memory:` for backtests** | one file per mode, WAL, survives restart, trivial backup | no horizontal scaling; fine for one bot |
| 5 | **Exits are market orders; entries are limit with a timeout** | getting out matters more than the last basis point | exit slippage is measured and reported |
| 6 | **Local stop monitoring in all modes, plus exchange-side stop in live** | the local monitor is the fallback if the exchange stop fails; the exchange stop protects you if the bot dies | the local monitor cancels the resting stop before exiting, so they cannot both fire |
| 7 | **Recovery adopts open positions instead of flattening on restart** | flattening on every restart would destroy a live position on a 5-second deploy | reconciliation must be clean before entries resume |
| 8 | **Rate/order windows use the injected clock** | replaying two days in two seconds must not look like a rate storm | `TokenBucket`/`SlidingWindowCounter` take `now_fn` |
| 9 | **Entry plans are keyed by client order id** | two limit entries on the same symbol-strategy must not share a plan, and a fill that arrives inside `place_order` must still find it | `OrderManager.plans` + `plan_for(order_id)` |
| 10 | **The dashboard can host the bot** | one command should give a working demo | `--no-bot` for read-only against a separately running bot |
| 11 | **The LLM journal is template-first** | a report must never depend on an API call, and numbers must be checkable | every number in LLM output is cross-checked against the day's JSON or the template wins |
| 12 | **Strategies S4/S5 are inert, not stubbed with fake signals** | a strategy that ships without validation teaches the wrong lesson | `MlSignal.evaluate` returns `None` until an approved model card exists |
| 13 | **Sensitivity judges the sign before the shape** | a wide, smooth plateau of *negative* scores was being reported as "broad plateau", which reads like approval | best cell ≤ 0 ⇒ "no edge", whatever the shape |
| 14 | **Parity needs a 1 200-minute tape, not 240** | short runs produced 0 decisions, so a "MATCH" proved nothing; the test now asserts decisions and fills are non-zero | parity is slow (minutes) and worth it |
| 15 | **IC is measured on non-overlapping samples** | forward returns over a horizon overlap bar to bar; counting the same move H times inflates the IC and shrinks its standard error to fiction | fewer observations, an honest noise band printed alongside every IC |
| 16 | **Fills are measured against the decision price** | the paper adapter used the fill price as the benchmark for market orders, so measured slippage was identically zero | `Order.reference_price`; slippage p95 is now +26 bps rather than 0 |
| 17 | **Cost stress reruns the backtest instead of subtracting fees** | a 2× cost world also changes which orders fill and which stops trigger; post-hoc subtraction flatters the result | `tradebot robustness` runs the engine twice |
| 18 | **No model card is committed, and `models/*.json` is gitignored** | a model trained on the synthetic generator would otherwise be able to trade after a `git pull` | `S4` reports `not_promoted` and returns nothing |
| 19 | **Promotion of a more complex model is enforced in code** | a rule kept in a document is a rule that gets ignored the first time the complex model looks good | `ladder.promote()` needs +10% net expectancy, profitable, in every window |
| 20 | **Venue abstractions before the venue** | §18.8 asks for the seams now so an NSE adapter is an adapter job, not a rewrite | `venues/` exists with no NSE broker adapter behind it |
| 21 | **Order-book features go NaN when the snapshot is stale** | carrying a five-minute-old imbalance forward produces confident, wrong numbers | staleness limit of five bars, tested |
| 22 | **The stream transport is injected, not imported** | no exchange access here, so a feed that could only be tested against a live socket would be untested code on a money path | `WebSocketFeed(config, clock, transport=...)`; the tests feed it recorded Binance frames |
| 23 | **Gap fill runs before the first frame after a reconnect, and windows end at that frame** | filling on connect used the wall clock, which on a replay never moves, so the window started where it ended and filled nothing - an outage that looks like continuity | the filled bars are emitted in order, ahead of the new frame; `stream` prints `gap-filled bars` |
| 24 | **Exchange symbols are rewritten to the configured ones at the boundary** | Binance streams `BTCUSDT`; the engine keys on `BTC/USDT`, so every bar would land under a symbol nothing looks up and the bot would sit flat while believing it was receiving data | `WebSocketFeed._canonicalise`, asserted in tests |
| 25 | **Meta-labelling may only remove trades** | a model that sizes positions is a second risk engine, unauthorized and unreviewed; §19.3 asks for a filter | the gate returns take/skip only; size stays with `portfolio/sizing.py` |
| 26 | **Sentiment can only shrink a position, never grow it** | a lexicon (or an LLM) reading headlines is easily wrong and easily manipulated | multiplier in [0.5, 1.0]; a broken feed leaves sizing untouched |
| 27 | **The Kite adapter uses `tag` as its client order id, with a lookup before every place** | Kite has no idempotent client id; a retry after a timeout would otherwise double a position | `_live_order_for_tag` runs first, and again after a transient failure |
| 28 | **NSE rules are checked locally before the order is sent** | a broker rejection for a 5-paise tick or a lot step has already been counted as an attempt, and pollutes the trade log | `Instrument.validate` raises `PermanentExchangeError`; nothing reaches the wire |
| 29 | **A closed NSE session is a permanent error, not a retry** | a MARKET order queued at 16:00 IST is a caller bug, and retrying it all evening is worse | `PermanentExchangeError("market closed")`, tested |
| 30 | **MLflow is an export, not a dependency** | logging every run through MLflow would put an optional, heavy library on the trading path, and the SQLite log is the thing the multiple-testing gate reads | `ai/tracking.py` writes the file-store layout; the layout is verified by reading it back with MLflow |
| 31 | **The meta gate may only veto, and it fails open** | §19.3 asks for a filter, not a second risk engine; a filter that blocks trades when its model breaks is indistinguishable from a dead market | `MetaEntryFilter` returns `(allowed, reason)`, `engine._entry_allowed` logs and allows on any error |
| 32 | **The slippage cap is fitted from our own fills, not assumed** | a hard-coded "max 25 bps" number is a wish; a p95 measured on this venue is evidence | the engine calibrates after 30 fills and caps entries at the affordable bucket; until then no cap applies and the recorder is the evidence |
| 33 | **Deflated Sharpe carries the skew/kurtosis correction** | a strategy whose returns are shaped like a short option looked safer than it was when only the trial count was corrected | `deflated_sharpe(..., skew, kurtosis)` plus `psr_probability`; the robustness report prints both |
| 34 | **A news outage is a count, not a fault** | a feed that times out, 502s or returns HTML must not stop a trading loop; the overlay keeps decaying what it already has | `news.NewsPoller` counts every failure, logs the type, and carries on; the poller hands the engine one long-lived `SentimentOverlay` so the engine's view and the poller's cannot drift |
| 35 | **Rung 4 is built, and rejected on evidence** | "not built because a lower rung has not won" is an excuse; the honest form is to build it and let the same promotion rule judge it | `SequenceModel` (window MLP, numpy, seeded) joins the ladder; on two simulated days it pays 2-3x the fees and returns -3 to -8 bps a bar, so the ladder keeps the baseline |
| 36 | **A session is logged once, at the end, and read back through the same reader** | streaming metrics to a tracking server mid-session would make the tracker a second source of truth and a failure mode on the trading path | `run --mlflow DIR` calls `session_run` + `export_runs` on shutdown; `experiments --read DIR` parses the store back, so the round trip is checked rather than assumed |
| 37 | **The research loop uses successive halving, not a cleverer optimiser** | a Bayesian optimiser would find a bigger number, and the bigger number would be an artefact of searching harder | cheap stages, keep the better half, judge the survivor on the full window, deflate by the attempts that were run; every candidate - including the ones that crashed - is a logged trial |
| 38 | **The cost budget is a refusal, not an optimisation** | at 15-minute horizons two taker fees plus slippage are most of the distance to the target, so a trade that needs the whole move to break even is a donation | check 17 refuses targets nearer than N× round-trip cost. The default (4) is neutral on the ten-day backtest on purpose (on a four-day window it vetoes one trade of twenty-seven): it was not chosen because it improved a backtest, and the docs record both what raising it does (49 trades at PF 1.14, 38 at 0.58) and the bug this check first exposed - a cost estimate built on the worst fill instead of the expected one, which made 12 trades look like a discovery |
| 39 | **Slippage has two numbers, and they are not interchangeable** | the size cap needs the pessimistic figure (what a bad fill costs); the cost budget needs the expectation (what this trade will cost). Using the worst fill for both turned a loss into a 12-trade "discovery" | `fallback_bps` = worst observed fill, used by the size cap; `expected_bps()` = sample-weighted mean of bucket means, used by `Engine._round_trip_cost_bps`. Tested separately, and `docs/RESULTS.md` keeps the wrong number it replaced |
| 40 | **MLflow is telemetry, so it can never stop a trade** | a tracking server is a nice-to-have that an operator points at from a laptop; a bot that dies because the laptop slept is a bot that cannot be trusted | MLflow imported lazily and only when `--mlflow-server` is set; the first client error disables the tracker for the rest of the session; an HTTP URI gets a 3-second TCP pre-check, because MLflow's own retry policy would otherwise stall the session for minutes before opening a run |
| 41 | **A model trained on the bot's own trades needs 200 of them before it gets a veto** | 92 trades produced a gate with AUC 0.16-0.26 that would have lost faster than the rule; a 13-feature logistic model on 50 rows fits noise | `learn` refuses to write a card below `MIN_TRADES`; promotion also needs 3 purged windows, +10% net R in every one, AUC >= 0.55 and a positive 2x-cost rerun. Features are decision-time only (ATR, stop, reward, hour) and labels are net R |
| 42 | **A ledger card expires, and every attempt is a logged trial** | a card describes a regime; left in place it keeps refusing trades with confident-looking reasons long after the market that produced it is gone. And an attempt nobody logged is an attempt nobody can deflate later | `run --ledger-gate` loads with `max_age_days` from `live_guards` (14) and a card past it is inert, saying so on stderr and in every veto reason. `learn` writes a `ledger_gate` row into the experiments table whatever the verdict, so repeated attempts show up in `tradebot experiments` |
| 43 | **A replay starts on the archive's first bar, and its depth is modelled and labelled** | hard-coding 2024-01-01 over a 2026 archive replayed zero trades and blamed the strategy; an archive holds no depth, so a bar-only replay gave 54 signals, 24 orders and 0 fills, which also looks like a broken strategy | `_sim_start`/`_sim_end` clip the window to the data; `ReplayFeed` builds a deterministic top-of-book from the bar close and prints `depth: modelled from bar close` with every result. A live feed on a simulated clock is refused |
| 44 | **A backfill's completeness is measured against the bars that had closed, not against the clock** | a real 30-day Binance fetch reported `stuck: true, complete: false` on two symbols that were complete: the window ended at `21:52:05` while the `21:52` bar was still open, so the last page legitimately advanced nothing and `expected` counted a bar that could not exist | `expected` excludes the unclosed bar; a page made only of unclosed rows means end-of-data, not `stuck`; a clean run now reports `kept == expected_bars` |
| 45 | **Health is three questions and three states, not a percentage** | a score invites tuning until it reads "fine"; the heal playbook has to branch on *can it do its job*, and a percentage cannot tell a retry from a replacement | every component reports liveness / readiness / correctness into `health.py`, which holds no policy; `HEALTHY`/`DEGRADED`/`FAILED`, the worst critical component owns the overall state, and every transition is a `health_change` event |
| 46 | **A heal that cannot be verified counts as a failure** | the easy version of self-healing reports "action taken" and moves on; an action whose effect you did not check is indistinguishable from a bug | a repair that keeps "succeeding" without changing anything escalates to a human instead of looping |
| 47 | **The playbook may only cancel, reduce, close or protect** | §20.1: healing decisions conservatively means never adding exposure while the system is already unhealthy | the row actions are an allowlist (`heal.SAFE_ACTIONS`); the only escalation lever is `killswitch.trigger`, the same one a human pulls |
| 48 | **Cooldowns and one-escalation-per-burst are in the frame, not in each row** | every row would otherwise reimplement (and forget) its own rate limiting | a broken repair costs at most one attempt per cooldown and one alert per burst |
| 49 | **The stuck-order gap was exits, not entries** | reading the code found `expire_stale_entries` already querying and cancelling entry orders, while the exit path had only a 120 s re-entrancy guard - a market exit the venue ignored left the position open with no second attempt | the `exit_stuck` row closes the loop, and three failed re-submissions escalate to L2 rather than retrying forever |
| 50 | **Paper mode skips the protective-stop row** | in paper the stop *is* the local monitor; "place a venue stop" is not a repair that can exist there | the row's detector returns False in paper and the skip is documented, rather than a fake success |
| 51 | **Re-running a comparison is not a repair** | a real five-minute paper run ended with `heal_failed: reconcile_mismatch` and an L1, because the row's "action" was to reconcile again, which reported the same disagreement the detector had already seen | the row cancels an unknown entry order (a protective stop or reduce-only exit is never "unknown" to that check) and only then re-reconciles; the regression test injects the order that caused it |
| 52 | **A restart is not evidence that the bot works** | starting a process is the easy half; a crash loop looks identical to a successful restart unless something waits for the pulse | the supervisor probes the heartbeat for `restart_verify_seconds` and escalates to L2 when it never returns, so `started` and `healthy` are different words in the code |
| 53 | **Flatten before restarting, and refuse the restart if you cannot** | a wedged process leaves positions whose protective orders may never have been placed; starting a new process into that is how a supervision win becomes a loss | the preflight is a precondition, not a courtesy: if it raises, no process is started and the incident says why |
| 54 | **Two processes on one account is worse than one wedged one** | the first version restarted without stopping the old process, which would double every future position | a live-but-silent process is stopped first; that is recorded as `supervisor_stopped_wedged` |
| 55 | **Disk is a floor, not a channel** | a channel list where the first success ends the attempt looks right and means the file writes replace Telegram, which is the failure this PR exists to prevent | channels carry `remote`, locals are written first, remotes are attempted after them, and only a remote success stops the retry queue |
| 56 | **A dead man's switch must latch, and refuse a reset while the pulse is missing** | a switch that re-arms itself the moment the heartbeat returns will flatten the position a human just re-opened; a reset that works while the bot is silent is a lie | `tripped` stays true until `reset()`, and `reset()` returns False while the heartbeat is still stale |
| 57 | **It is not armed in paper** | there is nothing to close, and a switch that fires during a laptop sleep teaches the operator to disable it | `armed` is False unless mode is testnet or live; the state dict says which |
| 58 | **The watchdog can now tell someone, which it never could** | its escalation went into the same SQLite file the wedged bot writes to, and the only transport was Telegram — so "Telegram is down" and "nobody was told" were the same event | `AlertRouter` reaches a phone through a second transport, and `tradebot health` reports `alerting` DEGRADED with the exact reason when only one is configured |

## Decisions I need from you (plan §17.4)

1. **Exchange for public data and (later) execution** — Binance, Bybit, CoinDCX, WazirX,
   Delta? Check availability and terms for India, and that its public REST endpoints
   are reachable from your machine/VPS. Until then the bot runs on the synthetic feed.
2. **Starting virtual capital** — default is 1,000 USDT; the hard capital cap for live
   is 250 USDT in `settings.yaml`.
3. **Coin list** — default BTC, ETH, SOL, BNB, XRP. Fewer coins means fewer fees and
   less correlation risk.
4. **Hosting** — your PC for paper (disable sleep, wired network) or a small VPS before
   live (static IP for the API whitelist). Docker Compose is included for either.
5. **LLM provider and Telegram bot token** — optional. Reports and alerts fall back to
   disk and logs without them.
6. **Quote currency** — USDT vs USDC vs INR pairs changes fees, tax records and depeg
   exposure. Record your choice here: `______________`.

## Next three moves (in order)

1. Get **real 1-minute history** for the five coins (backfill into the Parquet archive),
   then re-run `backtest`, `walk-forward`, `sensitivity`, `robustness` and `signals` on
   real data. Expect most strategies to be rejected; the suite is built to say so.
2. Start the **30-day paper soak** on live prices (`--feed ccxt`), recording books to the
   archive so the slippage model is calibrated on a real venue instead of the simulator.
3. Only then consider testnet, keys, and the live ramp - and only for a strategy that
   cleared every gate, including the 2× cost rerun.
